Build and simulate Pluronic F127 micelles loaded with a hydrophobic solute, at all-atom resolution.

Open the system designer  Pick what you want, get a system.json back, and look at the structure it built in 3D.

Accompanies Outer-core localization of a hydrophobic solute in Pluronic® F127 micelles from all-atom molecular dynamics.

The micelle in the box

34 chains of PEO100–PPO65–PEO100

data/f127_micelle_34.gro holds 69,802 polymer atoms equilibrated for 200 ns. Its poly(propylene oxide) core reaches 3.99 nm at the 90th percentile and the corona runs out to roughly 7 nm. The sequence is fixed: this one micelle is the structure every run starts from.

Choosing a size

How big a box?

One micelle sits in the box, and the 34 chains that ship are the only structure there is, so the box edge is the one size to choose. It decides how much water surrounds the micelle, and water is most of the cost. The default, 18 nm, leaves 2 nm between the corona and the box face where 1.5 nm is the least that keeps the micelle away from its own image.

Two loading routes

Start from both ends, not one

The tool builds both starting points, so the two can be compared.

Shell closure

A hollow poly(propylene oxide) shell is closed around solute placed at the centre. The solute starts as deep as it can go.

Uptake from solution

The solute is dispersed in bulk water and enters unaided.

Running it

From a topology to a production run

# GROMACS, python and the force field files
bash 0_check.sh

# put a CGenFF topology in library/<name>/ first
python3 -m f127load.check_params library/pyrene   # penalties
./f127 check                     # what is installed, what is missing
./f127 new                       # a few questions, writes system.json
./f127 test system.json          # a short pass of everything
./f127 run  system.json 100      # build, equilibrate, run 100 ns

./f127 build system.json         # stop at the tpr and run the MD yourself
./f127 pack  run_pyrene_solution # tar.gz that rebuilds anywhere
What each stage does

0_check.sh finds the local GROMACS, reads its version and writes compat.json. Below 2021 it uses Parrinello-Rahman instead of C-rescale. Below 2019 it stops.

1_build.sh reads system.json and sets up the run directory.

2_load.sh places the solute, by the shell route or in bulk water, solvates, adds ions and minimises.

3_equilibrate.sh minimises, then equilibrates at 310.15 K and 1 bar. No position restraints.

4_production.sh runs the production trajectory, compressed coordinates only.

5_analyze.sh produces radial density, uptake counts, RDF, interaction energies, hydration numbers, SASA, radius of gyration and solute-solute association.

What a library entry holds

Each molecule directory carries SMILES.txt with an isomeric SMILES, a .pdb and a .mol2 with 3D coordinates, and once CHARMM-GUI has been run, the topology and RESNAME.txt. The pyrene entry also keeps CHARMMGUI_JOBID.txt so the parameter run can be traced.

Parameters

Where a topology comes from

CHARMM-GUI Ligand Reader and Modeler returns a CHARMM36/CGenFF topology for the molecule with a penalty on every charge and bonded term. Drop what it sends into library/<name>/; check_params reads the penalties, and above about 50 on charge the molecule should be reparameterised.
